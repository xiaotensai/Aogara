## 三、"用户友好版"修复方案（下一轮执行）

### P0-1 修 U-02（账号丢失）——二选一
- **方案 A（推荐，最小改动）**：`setup_add_account` 成功后，让后端把新配置同步回前端 store。
  - `setup_add_account` 后端在写盘后发一个 `config-changed` 事件（或返回完整 cfg 让前端 `setStored`）；前端 `next()` 拿到返回的账号列表，把新账号合并进 `draft.pool.accounts`（及 `selected_id`），后续 `finish()` 的 `final` 就带账号。
  - 关键：`finish()` 的 `final.pool` 必须以**当前磁盘/内存配置**为准，而不是启动快照。
- **方案 B（重构）**：`finish()` 不再整体 `update_config`，改为逐段 update（只写 general/platform/capture/bot 等向导真正改的段），`pool` 段完全不碰。
  - 更稳，但改动面大，需回归向导所有步骤。
- 验证：向导添加测试账号 → 完成 → 打开号池应看到该账号（无需重新添加）；重开程序账号仍在；`config.toml` 含 `[[pool.accounts]]`。

### P1-1 修 U-03（端口文案）
- 会话页 `Sessions.tsx:592` 改为"每个账号独立运行，最多 8 个；添加后点开浏览器即可"，删"端口"；
- `:737-739` 列表列改为"运行状态 / 数据目录"（端口收进 hover title 或高级信息）；
- `:474` toast 去掉"（端口 63504）"，只显示"已添加 XXX → 会话 N"；
- 玩家全程不接触"端口/profile/CDP"这类词，除非开启"开发者模式"。

### P1-2 修 U-04（流程割裂）
- 号池添加账号成功后，提供显式引导："已添加，去【多开会话】一键建会话"按钮，或直接在号池保存后自动建会话（需评估与 slot1 的关系）；
- 向导里第 1 个账号必须确认已落到 `pool.selected_id` 并驱动 slot1，避免"加号却没会话"。

### P2-1 修 U-01（图标残留）
- `Setup.tsx` 的 GitHub/Discord 按钮改为条件渲染：`{AOGARA_XXX_URL && <Button …/>}`；四个空常量则该按钮整块不显示。
- 欢迎页 `links_label` 也要注意：若两个按钮都隐藏，标签文字一并隐藏。

### P2-2 修 U-05（卡死）
- `Setup.tsx` 的 `get_config` catch 里 `setErr` 提示"配置读取失败"，并提供"使用默认配置继续"按钮（用 `AppConfig::default` 等价的前端默认值）；
- `draft` 为 null 时渲染错误卡片 + 重试，而不是无限"加载中"。

### 不修复（保留现状，属设计）
- 后端 `create_session` 自动分配端口本身正确，不改分配逻辑；
- 号池账号密码明文存 `config.toml` 是现有设计（隐私提示已在向导/号池给出），本轮不动。

## 七、U-06：号池要求玩家手工加调试端口（2026-11-25 00:00–00:08）

> 用户真实环境实测反馈："slot1: 号池需要固定游戏调试端口：请在 config.toml 的
> `[capture.chromium].extra_args` 加 --remote-debugging-port=63503"。
> 这暴露 U-03 的误判——它**不只是文案暴露端口术语，而是功能真的跑不起来**。

### 7.1 根因（真实机制，非文案）

- 号池/多开命令经 `pool_cdp_port()`（`commands.rs:235`）→ `game_cdp_port()` → `parse_fixed_cdp_port()`
  从 `[capture.chromium].extra_args` 读固定游戏调试端口；读不到就直接报这句错误（`POOL_CDP_PORT_REQUIRED`）。
- 浏览器启动（`launch.rs:109 remote_debugging_config`）在 `extra_args` **没有**固定端口时，会
  `pick_remote_debugging_port()` 分配一个**随机端口**——游戏能开、能打，但号池不知道端口是多少。
- 首次运行向导写出的 config 用的是 `AppConfig::default()`，而 `capture.rs` 默认的
  `extra_args: vec![]` 是空的；模板 `config.example.toml` 却有 `--remote-debugging-port=63503`。
  **两者不一致** → 向导生成的配置缺端口 → 玩家一点号池功能就被要求手工改配置文件。
- 多开约定：slotN → 63502+N（slot1=63503），基础配置必须是 63503。

### 7.2 修复（两处）

| 文件 | 改动 |
|---|---|
| `src/config/capture.rs` | `ChromiumConfig::default()` 的 `extra_args` 默认带上 `--remote-debugging-port=63503` + `--window-size=1280,720`（与模板一致）——**新配置从源头就带端口** |
| `src/config/mod.rs` | `load_config` 新增 `migrate_fixed_cdp_port()`：已有配置若没有显式端口，自动补 63503，内存+磁盘同时生效；**不覆盖用户显式设置的端口** |
| `src/config/mod.rs`（测试） | 新增 3 个单测：default 带端口 / 空 extra_args 迁移 / 显式端口不被覆盖 |
