## 一、总体判断

本次复查发现的可优化点集中在两个领域：

1. **`--remote-debugging-port` 解析逻辑重复**——同一件事（从 `extra_args` 里把游戏浏览器 CDP 端口抠出来）在 4 个文件里各自实现了一遍，且规则不完全一致，是最大的重复与隐患来源。
2. **号池（pool）与自动出牌（autoplay）的 CDP 输入层边界**——点击已复用，键盘输入尚未复用，存在「未来出现第三套键盘实现」的风险。

其余是低成本的常量提取与辅助函数封装。下面逐项给出位置、证据、改法与收益。

## 二、优化点清单

### 优化点 1：统一 `--remote-debugging-port` 解析（最高优先）

**现状：同一解析逻辑散落 4 处，规则不一致。**

| # | 位置 | 实现 | 说明 |
|---|---|---|---|
| A | `pool/mod.rs:245-264` | `game_cdp_port(extra_args)` | 返回 `Option<u16>`，`p != 0` 才算有效 |
| B | `capture/chromium/launch.rs:102-117` | `parse_fixed_debug_port(extra_args)` | 返回 `Option<u16>`，复用 `parse_remote_debugging_port` |
| C | `capture/chromium/launch.rs:119-144` | `remote_debugging_config(extra_args)` | 返回 `Result<RemoteDebuggingConfig>`，无用户端口时随机挑端口 |
| D | `lib.rs:535-537` | 内联 `.find(|a| a.starts_with("--remote-debugging-port="))` | **只认 `=` 写法，不认分离两参数写法**，且只用于日志打印 |
| E | `ipc/commands.rs:975-981` | 内联 `.map(|a| if a.starts_with(...))` | 端口重写（多会话 63502+idx），只认 `=` 写法 |

**问题：**
- A/B 行为一致但各写一遍；D/E 是「只认 `=` 写法」的简化版，若某天 `extra_args` 里出现 `--remote-debugging-port 63503`（分离写法），A/B 能识别、D/E 会漏。
- B 还带了一整套 `RemoteDebuggingPort`/`parse_remote_debugging_port`（`launch.rs:146-169`），与 A 的 `u16` 解析是平行实现。

**改法：**

把 A 提升为公共工具函数（建议放到 `src/util/mod.rs` 或新建 `src/cdp_port.rs`），统一语法：

```rust
/// 从 extra_args 提取 --remote-debugging-port，支持 `=N` 与分离两参数两种写法。
/// 返回 None 表示未配置；端口 0 视为「未指定」（与 Chromium 的 Auto 语义一致）。
pub fn parse_fixed_cdp_port(extra_args: &[String]) -> Option<u16> {
    // 逻辑同 pool::game_cdp_port，支持 strip_prefix("--remote-debugging-port=") 与 == "--remote-debugging-port"
}
```

然后：
- A 改为 `pub use` 或一行转发（`pub fn game_cdp_port(a) -> Option<u16> { util::parse_fixed_cdp_port(a) }`，保留旧名避免 8 处调用点改动，或直接批量替换调用点）。
- B 改为调用上述公共函数，删除本地重复实现。
- C 保留（它有「随机挑端口」的额外职责，但可改成：先 `parse_fixed_cdp_port` 拿固定端口，没有再随机挑）。
- D、E 改为调用公共函数，消除「只认 `=` 写法」的不一致。

**收益：**
- 消除 3 份重复解析 + 2 份简化版，未来改端口规则只动一处。
- 修复 D/E 潜在漏判分离写法的隐患。

**影响范围：**
- 纯重构，不改变运行时行为（公共函数逻辑 = 现有 A 的逻辑）。
- 涉及文件：`util/mod.rs`（新增）、`pool/mod.rs`、`capture/chromium/launch.rs`、`lib.rs`、`ipc/commands.rs`。
- 需回归：启动装配日志打印、多会话端口重写、号池连接、探活。

### 优化点 2：错误提示字符串提常量 + 端口取值辅助函数

**现状：**
- 错误串「号池需要固定游戏调试端口：请在 config.toml 的 [capture.chromium].extra_args 加 --remote-debugging-port=63503」在 `ipc/commands.rs` **一字不差重复 3 处**（行 611-612、632-633、1463-1464，其中 611 和 632 两处文案还略有差异：一处带 `[capture.chromium]` 一处不带）。
- `pool_mod::game_cdp_port(...).ok_or_else(|| "...".to_string())?` 这个「取值 + 包错误」模式在 `commands.rs` 出现 **8 次**（行 611、632、693、886、1192、1463、1752 等），每次都要重复写错误串。

**改法：**

```rust
// 模块顶部
const POOL_CDP_PORT_REQUIRED: &str =
    "号池需要固定游戏调试端口：请在 config.toml 的 [capture.chromium].extra_args 加 --remote-debugging-port=63503";

/// 从 cfg 取游戏 CDP 端口，缺配置则报统一错误。
fn pool_cdp_port(cfg: &Config) -> CmdResult<u16> {
    pool_mod::game_cdp_port(&cfg.capture.chromium.extra_args)
        .ok_or_else(|| POOL_CDP_PORT_REQUIRED.to_string())
}
```

8 处调用点改为 `let port = pool_cdp_port(&cfg)?;`。

**收益：**
- 文案统一（顺带修正 632 处漏 `[capture.chromium]` 的不一致）。
- 8 处重复的 `ok_or_else` + 长字符串缩成 1 行，易读易改。

**影响范围：**
- 纯文本/封装重构，行为不变。
- 涉及文件：仅 `ipc/commands.rs`。
- 需回归：号池相关命令（probe_login / switch_account / enter_room 等）在「未配置端口」时的报错文案。

### 优化点 3：键盘输入逻辑评估复用（中优先，需决策）

**现状：**

- `autoplay/cdp_input.rs` 只有**点击**三件套：`dispatch_click`(行28) / `dispatch_click_shaped`(行44) / `evaluate_canvas_rect`(行110)。
- `pool/mod.rs` 的**键盘**四件套是独立实现：`key_map`(行174) / `dispatch_key`(行196) / `key_type`(行216) / `clear_unity_field`(行234)。
- 号池的点击已经复用 autoplay（`click_norm` 调 `dispatch_click_shaped`），但键盘没复用，因为 autoplay 侧当前没有键盘函数。

**问题：** 键盘输入逻辑（字符→CDP key 事件的映射、Shift 修饰、逐字符 35ms 间隔、Ctrl+A 清空）目前只有 pool 一份。若将来 autoplay 或其它模块也要往 Unity 画布打字，大概率会再复制一份，形成第三套。

**改法（二选一，需确认）：**

- **方案 A（推荐，纯搬运）**：把 `key_map` / `dispatch_key` / `key_type` / `clear_unity_field` 从 `pool/mod.rs` 迁到 `autoplay/cdp_input.rs`，`pub` 导出，`pool/mod.rs` 改为 `use` 调用。理由是它们本质是「Unity WebGL 画布的 CDP 输入原语」，与点击三件套同层。
- **方案 B（暂不动，加注释）**：若确定 autoplay 永不使用键盘输入，则保持现状，仅在 `pool/mod.rs` 与 `cdp_input.rs` 各加一行注释，明确「键盘输入只在 pool，勿在 autoplay 重复实现」，避免未来无意识地复制。

**收益：**
- 方案 A：消除「未来出现第三套键盘实现」的风险，键盘与点击同层同构。
- 方案 B：零改动成本，靠约定防重复。

**影响范围：**
- 方案 A：中——涉及 `pool/mod.rs`（删 4 函数 + 改 import）与 `cdp_input.rs`（增 4 函数），需回归号池登录（换号输入邮箱密码、清空字段）全流程。
- 方案 B：无行为影响，仅注释。

### 优化点 4：`pool/mod.rs` 内部小重复（低优先）

**现状：** `dispatch_key` 函数（行196-213）与 `key_type`/`clear_unity_field` 的关系已较清晰，但 `key_map` 的返回类型是裸元组 `(String, String, i64, bool)`，四个字段（key/code/vk/shift）语义靠位置约定，可读性一般。

**改法（可选）：** 把 `key_map` 返回改为具名结构体 `struct KeyStroke { key: String, code: String, vk: i64, shift: bool }`。

**收益：** 纯可读性，消除「位置元组」的心智负担。
**影响范围：** 仅 `pool/mod.rs` 内 `key_map` 与 `key_type` 两处。
