## 一、敏感数据与脱敏（最高优先级）

| # | 问题 | 根因 | 处理 / 规避 | 状态 |
|---|---|---|---|---|
| S1 | 源码注释里有本机账号痕迹 | `src/pool/mod.rs` 顶号诊断注释含 `p-accountA` + 真实 UID `<UID>`；`src/bridge/tenhou/mod.rs` 测试注释含本机日志路径 `a-local-run/...` | 在 H 盘副本里改成泛化描述；**F 盘原件保留作为证据链**（双轨：本地留证据 / 公开版脱敏） | ✅ 已修 |
| S2 | 配置模板首版带出真实凭据 | 生成脚本把第 2–5 个账号块一起放进 tail，内含真实邮箱/QQ/密码 | 改为只保留 1 个空账号块（tail 从 `[test]` 段开始），5 个身份字段全置 `""` | ✅ 已修 |
| S3 | 公开文档 72+ 处个人信息 | 主文档/手册/改名清单里有真实邮箱、UID、昵称、登录名/密码串、`%USERPROFILE%`、`<安装目录>` | 脚本批量替换为占位符（`user@example.com`/`<UID>`/`玩家A`/`%USERPROFILE%`/`<安装目录>`） | ✅ 已修 |
| S4 | 脱敏替换顺序错误导致漏网 | 先替换账号名 `accountA→accountA`，使 `user@example.com` 变成 `user@example.com`，邮箱规则再也匹配不上 | **必须先邮箱后账号名**；脱敏后必须再跑一次全量 `grep` 复验（本轮复验才揪出 `<登录名占位>` 等登录名/密码串） | ✅ 已修，重点经验 |
| S5 | 测试账号配置混进公开目录的风险 | 真实账号实测时，配置含邮箱+明文密码，若放在预演目录内会污染公开包 | 测试配置放公开包目录**之外**的独立 `account-test/`；验证后**整目录删除**；对 repo/stage/zip 全量扫描确认无真实邮箱/密码/UID | ✅ 已清理，扫描 CLEAN |
| S6 | 11 类敏感数据需要逐类排除 | 配置账号、profiles Cookie、accounts.json 昵称、3 个 `.key`、CA 私钥 `aogara-ca.pem`、logs/history/runtime、stdout 日志、8 个旧 exe、shots 截图、注册表备份 json、文档 | 建立敏感数据清单（方案 §2），`.gitignore` 融合上游 + 11 类补充；zip 打包脚本需**显式排除**（`.gitignore` 不作用于 zip） | ✅ 清单已建，zip 已验 |

> **教训**：脱敏是一次"写完必须扫、扫完再扫"的活。三轮替换才真正做到 0 命中——第一轮漏顺序、第二轮漏登录名/密码串、第三轮才干净。

## 三、环境与工具限制（非代码缺陷）

| # | 问题 | 现象 | 处理 / 规避 | 状态 |
|---|---|---|---|---|
| E1 | UI 调试口 631xx 始终无法 bind | WebView2 子进程命令行**确实带** `--remote-debugging-port`（63120/63121/63122 都试过，H 盘 + 生产目录都试过），但端口从未监听，`DevToolsActivePort` 文件也不存在 | 无法用 CDP 驱动向导 UI 自动填表；核心逻辑改用单元测试覆盖。**关键对比：游戏 CDP 63503 正常可用**——所以能读游戏页 localStorage 验证登录身份，只是 UI 那个口不通 | ⚠️ 环境限制，待 CDP 可用环境补验 |
| E2 | `Add-Type` 被安全策略拦截 | 想用 .NET `ZipFile` 检查 zip 内容，被拦截（"compiles and loads .NET code at runtime"） | 改用 Python 标准库 `zipfile` 遍历，等效且干净 | ✅ 已绕过 |
| E3 | 从 Bash 调用 PowerShell / 从 PowerShell 启动 cmd 被拦截 | "Invoking PowerShell from Bash bypasses security checks"、"Starting cmd.exe from PowerShell bypasses..." | 用对应专用工具（PowerShell 工具跑 PS、Bash 工具跑 bash），不跨 shell 嵌套 | ✅ 已规避 |
| E4 | `Start-Process` 环境变量字典报错 | 系统里 `HTTPS_PROXY` 与 `https_proxy` 大小写重复键导致 `ArgumentException` | 避免在 PS 里用 `Start-Process` 传整环境；改用 bash 行内赋值或直接前台式启动 | ✅ 已规避 |
| E5 | 截图需虚拟桌面授权 | `gui_screenshot` 返回 `credential_required`，要求用户授权 | 不抢占用户桌面焦点，放弃 GUI 截图这条路，改用日志/CDP/DOM 证据 | ✅ 已规避 |
| E6 | 后台启动器 shell 退出带走子进程 | `cd && VAR=x exe &` 方式启动，命令返回后进程消失 | 用工具的 `run_in_background` 机制启动，不用 shell 的 `&` | ✅ 已规避 |
| E7 | 单实例保护导致 exit 1 / 新实例起不来 | 收尾时重复启动 exe（已有实例在跑），或测试实例没停干净就启动新的 | 启动前先确认并 `Stop-Process` 现有实例；看到 exit 1 先查进程状态，不盲目重试 | ✅ 已核实 |
| E8 | 环境变量传给 WebView2 不稳定 | bash 行内赋值 / `export` / cmd `set` 多种方式，WebView2 有时拿到参数有时没有 | 本轮 E1 是端口不 bind（参数其实带上了），不是环境变量问题；不必再试各种赋值方式 | ℹ️ 已定位 |

## 四、架构与设计认知（实现向导时发现）

| # | 认知 | 意义 | 状态 |
|---|---|---|---|
| A1 | `multi.sessions` 是遗留字段，真正工作会话来自 `sessions.dynamic.json`（由 `create_session` 维护） | 向导多开必须走 `create_session`，**不能**往 `multi.sessions` 写；否则配了也不生效 | ✅ 已按此实现 |
| A2 | `state.config` 与 slot1 session 的 config 是**同一个 Arc**（`state.rs:192 config: session.config.clone()`） | 写一次即可同时刷新 session 与 Settings；不要写两遍（最初的冗余写法读自己再写自己，还会死锁） | ✅ 已修正 |
| A3 | `resolve_profile_dir` 要求非空路径必须是绝对路径 | 向导的 profile 路径要么留空（走可移植 `./chrome-profile`），要么用程序运行时拼出的绝对路径；**禁止**手写相对路径或写死 `<安装目录>` | ✅ 已按此实现 |
| A4 | Rust move 语义：`cfg` 写入 state 后不能再读 | 提前把 `count` 算出来，避免编译错误 | ✅ 已修 |
| A5 | 生产账号 coords 为空仍能登录 | 登录靠邮箱/密码自动填充，coords 只用于进房等 UI 点击；向导写入完整 coords 比生产配置更完整 | ℹ️ 认知 |

## 六、真正公开打包前的检查清单（由问题清单导出）

1. **脱敏复验三连**：源码注释 → 配置模板 → 文档，每类替换后都跑 `grep -niE` 全量扫描，且顺序"先邮箱后账号名"。
2. **zip 显式排除**：`config.toml`/`profiles/`/`logs/`/`ca/`/`*.key`/`*.pem`/`accounts.json`/`tools/` ——不要依赖 `.gitignore`。
3. **打包脚本改造**：`scripts/package-zip.sh` 的 3 处 `akagi→aogara`、运行时路径改指 `app/runtime/`、纳入 `THIRD_PARTY_NOTICES.txt` 与 `config.example.toml`。
4. **单测兜底**：`cargo test --lib` 跑 `setup_wizard_add_account_logic`；前端 `npm run build` 类型检查。
5. **GUI 补验**（唯一未闭环项）：在 CDP 可用环境，干净包首次运行 → 向导填账号 → 完成 → 能登录。
6. **首次 commit 四步检查**：`git status --short` 看白名单 → `git diff --cached | grep` 敏感串 → 体积检查 → 有命中立刻 `git reset`（方案 §4.3）。
7. **不用 reg.exe**：注册表改动交给用户手动跑 `.reg`；备份用 PowerShell cmdlet 存 JSON。
