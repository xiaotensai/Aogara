### 1.2 做法：新增 `scripts/sanitize-source.ps1`（或 .py）

| 匹配 | 替换为 | 位置 |

| `p-accountA`、`p-accountA[13]` | `p-accountA`、`p-accountB` | `pool/mod.rs` 注释 |
| `<UID>`、`<UID>`、`<UID>`、`<UID>`、`<UID>` | `<UID>` | 注释/文档 |
| `accountA`、`accountB` | `accountA`、`accountB` | 注释 |
| `\d{6,12}<邮箱域名>`、`\d{6,12}<邮箱域名>` | `user@example.com` | 全文本（**先邮箱后账号名**） |
| `<登录名占位>\d*`、`xiao\d{6,}` | `<登录名占位>` / `<密码占位>` | 全文本 |

| `%USERPROFILE%`、`<安装目录>`、`<安装目录>` | `%USERPROFILE%` / `<安装目录>` | 全文本 |

**顺序铁律**：邮箱规则必须在账号名规则之前（问题清单 S4）。

## 二、R2 — `scripts/package-zip.sh` 改造

### 2.1 现状（已核查，问题点）
`scripts/package-zip.sh` 150 行，问题：
- 包名/目录/exe/README 全是 `akagi`（第 6-8、19、40-42、49、85、91-92 行等约 9 处）
- 运行时路径 `runtime/<triple>/`（第 55-56 行）——本机运行时在 `<安装目录>\app\runtime/`，`fetch-runtime.sh` 下载到仓库根 `runtime/`，**两条路径不一致**
- README 尾部外链 `https://github.com/shinkuan/AkagiV3`（第 132 行）——死链/上游链接
- 不含 `THIRD_PARTY_NOTICES.txt`、`config.example.toml`
- 无显式排除私有数据（虽然 staging 是新建的，但要防呆）

### 2.2 改造内容（逐项）

**A. 品牌名替换（9 处）**
```
akagi → aogara（PKG / EXE / README 文案 / 目录名）
```
保留上游署名：README.txt 里写"Aogara（基于 Akagi，Apache-2.0）"，不抹掉上游。

**B. 运行时路径——两种解法，选其一**
- **解法 1（推荐，零依赖）**：改脚本读 `<安装目录>\app\runtime/` 的布局
  ```bash
  PY_SRC="$ROOT/app/runtime/python/$TARGET"
  UV_SRC="$ROOT/app/runtime/uv/$TARGET"
  ```
  但这要求生产仓库目录下有 `app/runtime/`——当前生产源码在 `_setup/src/Aogara-3/`，而 app 在 `<安装目录>\app\`，**不同根**。需要一个 `RUNTIME_ROOT` 变量指向 `<安装目录>/app`，脚本里做成可覆盖：
  ```bash
  RUNTIME_ROOT="${RUNTIME_ROOT:-$ROOT/app}"
  PY_SRC="$RUNTIME_ROOT/runtime/python/$TARGET"
  UV_SRC="$RUNTIME_ROOT/runtime/uv/$TARGET"
  ```
  执行时 `RUNTIME_ROOT="<安装目录>/app" scripts/package-zip.sh x86_64-pc-windows-msvc`。
- **解法 2（标准，适合 GitHub）**：按上游原设计，先 `scripts/fetch-runtime.sh x86_64-pc-windows-msvc` 把运行时下载到仓库根 `runtime/<triple>/`，脚本不用改路径。代价：下载 210 MB（本机慢）。

> 方案建议：**本机出包用解法 1**（复用已有运行时，秒出），**GitHub CI 用解法 2**（从零构建）。脚本用 `RUNTIME_ROOT` 环境变量兼容两者。

**C. 纳入正式资产**
```
cp "$ROOT/config.example.toml"        "$STAGE/config.example.toml"
cp "$ROOT/THIRD_PARTY_NOTICES.txt"    "$STAGE/THIRD_PARTY_NOTICES.txt"
cp "$ROOT/README.md"                  "$STAGE/README.txt"   # 用开源版 README，弃脚本内 heredoc
```
即**删掉脚本第 84-133 行的 heredoc README**，改为直接复制仓库里的正式 README（R3 落地产物），避免两处维护。

**D. 显式排除私有数据（防呆）**
在 `cp`/`zip` 前后加检查：
```bash
# staging 建成后、压缩前，扫描禁用项
if find "$STAGE" \( -name 'config.toml' -o -name '*.key' -o -name '*.pem' \
     -o -name 'accounts.json' -o -path '*/profiles/*' -o -path '*/logs/*' \
     -o -path '*/ca/*' \) -not -path '*/certifi/cacert.pem' | grep -q .; then
  echo "ERROR: private data leaked into staging" >&2; exit 1
fi
```
注意 `certifi/cacert.pem` 是 pip 公共 CA，白名单放行。

**E. zip 内容校验（可选但推荐）**
打包后打印条目数与体积，供人工核对（应约 3258 条 / 85 MB）：
```bash
echo "entries=$(unzip -l "$ARCHIVE" | tail -1)"
echo "size=$(du -h "$ARCHIVE" | cut -f1)"
```

### 2.3 验证
1. `bash -n scripts/package-zip.sh` 语法检查
2. 用 `RUNTIME_ROOT="<安装目录>/app"` 在本机出一次包到 `dist/`，检查：包名 `aogara-1.1.0-windows-x64.zip`、exe 名、运行时路径、4 个正式文件齐全、无私有数据
3. 解压到全新目录启动一次（复用 V4/V5/V16），确认可运行
